Attention v2 设计分析素材
对应已验证 RTL：977fffec5825ba0eeb639de28a14e5a61c795f3b
证据：experiments/delivery_full/manifest.json
这是答辩准备素材，不是最终报告。

1. 算法怎样落到电路

当前电路先存入 Q 和全部 K/V，然后分阶段计算：
LOAD_Q → LOAD_KV → DOT → EXP → UPDATE → 除法归一化 → OUTPUT。
算法上可以按 token 描述注意力，当前代码实际并不是每收一组 K/V 就立即完成该组计算。
DOT 算完全部 8 个 Score，期间维护 max_score；EXP 才能使用全局最大值。
distance=max_score-Score；查表得到权重整数编码 [16,6,2,1,0...]。
UPDATE 逐项执行 ACC[dim]+=weight[token]*V[token][dim]。
EXP 同时累加 L；最后四个 ACC 依次共用一个除法器得到四项输出。

主模块 rtl/attention_ip.sv：存储、状态控制、点积和加权累加。
rtl/exp_lut.sv：组合查表，无独立时钟周期。
rtl/unsigned_divider.sv：36 位迭代除法器，每次只算一个输出分量。
综合前有两个乘法运算：Q×K 与 weight×V；不是 8 个 token 同时运算，
也不是只有一个乘法器在这两种运算之间共享。除法器由四个输出分量共享。

2. 一轮需要多少拍

以空闲状态接受 start 的上升沿为相对第 0 拍，启动当拍不接收输入。
无输入暂停时，后续执行区间如下（用进入上升沿前的状态划分）：
相对拍号   状态          拍数     作用
1..4       LOAD_Q          4     存入 Q 的 4 个分量
5..36      LOAD_KV        32     每拍同时存 1 个 K 分量和 1 个 V 分量
37..68     DOT            32     8 个 token，每个点积用 4 拍
69..76     EXP             8     每拍查一个权重，同时累加 L
77..108    UPDATE         32     8×4 次加权累加
109..260   NORM_START/WAIT 152   每个分量 1 拍启动＋37 拍等待，共 4 轮
261..264   OUTPUT          4     依次输出 O[0]..O[3]
总计                     264

36 位除法器逐位迭代；父模块还需在后一个时钟边沿观察到 done，故 WAIT 为 37 拍。
第 264 拍 done 与第 4 个 out_valid 同拍。下一笔 start 最早在第 265 拍被接受，
因此无停顿、立即重启的启动间隔是 265 拍，不能把延迟 264 拍直接当成启动间隔。
输入阶段每少一次有效输入就增加一拍。示例暂停 Q 三拍、KV 三拍，总计 270 拍。
10ns 是测试台时钟周期；无停顿的模拟耗时 2640ns，不代表已验证物理最高频率。
归一化占 152/264≈57.6%，是当前周期数的大头；缩小除法器位宽是潜在优化，尚未实施。

3. 暂停与复位

start 只在 IDLE 接受；忙时 start 不启动新任务。
LOAD_Q 仅在 q_valid=1 时写 Q；LOAD_KV 仅在 kv_valid=1 时写 K/V。
data_ready 只表示当前处于装载阶段；发送端仍须按约定先 Q、后 K/V。
输入有效信号为 0 时，装载位置计数器和目标存储位置保持不变。
内部计算阶段连续推进，没有任意阶段暂停接口。
输出没有 ready/反压，接收端必须连续接住四拍。
低有效异步复位会放弃当前任务、回到 IDLE；重新 start 后重装所有输入。
数据存储不逐项复位，因为使用前会写满；控制与累加状态会复位。

4. 存储与实际综合统计

以下是 RTL 声明的数据缓冲容量，不等于全部触发器数量：
Q：4×8=32 bit；K：32×8=256 bit；V：32×8=256 bit；
Score：8×18=144 bit；Weight：8×5=40 bit；
ACC：4×16=64 bit；输出缓存：4×8=32 bit。
合计 824 bit=103 byte。另有 L、最大分数、点积暂存、输出端口寄存器、
状态、计数器以及除法器内部状态。不要用 824 bit 冒充电路全部存储。

本次 Yosys 通用综合：5350 个逻辑单元，1041 位寄存器，check -assert 通过。
该数字含控制、数据与除法器寄存器，并受优化影响。
通用单元不是 FPGA LUT/DSP/BRAM 数量；当前综合未给出器件面积、功耗或最高频率。
综合网表已实际编译并运行 1725 个案例，输出及周期与对应 RTL 端口仿真一致。
这属于选定案例的功能验证，不是形式等价证明，也不是带布线延迟的时序仿真。

5. 扩展到 S=256，保持 d=4

当前源码写死 S=8。本节说明如果沿用串行结构需要改什么，不能直接改一个参数就运行。
token 从 3 位改为 8 位，K/V 地址从 5 位改为 10 位；循环结束条件与缓存深度同步修改。
Q/K/V/O 仍为 int8；Score 仍为 signed 18，因为点积长度 d 没变。
Weight 仍为 5 位；L 最大为 256×16=4096，需要 unsigned 13 位。
ACC 范围为 -524288..520192，需要至少 signed 20 位；符号扩展及测试台也要修改。
现有 36 位除法器足够，但相关输入拼接宽度不能继续沿用旧的固定常数。

按 ACC 使用 20 位计算的数据缓冲：
Q 32 + K/V 16384 + Score 4608 + Weight 1280 + ACC 80 + 输出 32
=22416 bit=2802 byte；仍未含 L、控制与除法器内部状态。
这些数组可能适合映射 RAM，但是否能推断出 BRAM，要结合器件、读写端口和综合方式验证。

同一串行调度、36 位除法器且没有暂停时：
周期=4+4S+4S+S+4S+152+4=13S+160。
S=8 为 264 拍；S=256 为 3488 拍，约增至 13.21 倍。
最早启动间隔预计为 3489 拍，需扩展后重新仿真核对。
每轮输入字节数=4+2×S×4：68 byte → 2052 byte；输出均为 4 byte。
K/V 装载拍数 32 → 1024，瞬时端口仍每拍接 2 byte。
如要保持相同每秒查询数，平均输入带宽需约 30.18 倍；若保持本串行架构和时钟，
查询吞吐量则降低，不能同时宣称吞吐不变且带宽不变。
这里讨论的是 S=256、d=4，不是题目可能另列的 S=256、d=64 进阶任务。

6. 正确性与精度应分开陈述

RTL 与整数模型一致、暂停不丢数据、重跑一致，均已有测试证据。
LUT 的 4 位小数会把 distance>=4 的权重量化成 0；本轮对理想浮点结果的
最大绝对误差约 28.978，出现在专门构造的边界/极端案例，不应写成“误差可忽略”。
完整误差分布与最差案例保存在每个种子的 numerical_audit.json 和 high_precision_errors.csv。
当前实现尚未做器件综合、物理时序或上板；以上扩展也尚未写入 RTL。
